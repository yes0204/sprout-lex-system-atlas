모듈별 개선안 — 실제 회신 요약

<Michael>요청 접수·검증·전달·결과 형식·오류 반환 source_filter를 전체 경로에 실제 적용하거나 미지원으로 명시 거절하는 계약이 우선이다. 오류 공통 구조·추적 ID를 정하고, 직접 원문 경로 분리는 API의 키워드 분기가 아닌 Emily의 그래프 변경으로 진행한다.

<Grace>벡터색인 색인 청크의 부모 article_id를 보장하고, 검색 원점수·가산점·색인 판을 구분한다. 점수 범위와 임계값의 관계는 실제 라이브러리/설정/분포로 검증해야 한다. 한 조문 청크가 후보를 점유해 복원 뒤 문서 수가 줄어드는 경우도 시험한다. article_id 누락은 조건부 위험이며 실제 색인에 누락됐다고 확인한 것은 아니다.

<William>원문저장소 본문과 표시 메타데이터가 같은 판 선택 함수를 사용하게 하고 복원 결과에 판 ID·해시·출처 좌표를 함께 반환한다. current_meta에는 현행 본문 조회와 달리 ORDER BY가 없어 여러 유효판이 겹치면 다른 판 표시 가능성이 있다. 실제 DB에서 발생했는지는 미확인이다. 검색 청크 판과 복원 판도 비교한다.

기초 온톨로지 설계(사전·범위 담당) — 실제 회신 요약

<James>사전·범위 규칙 개념사전은 이미 있다. 고정 YAML에서 5개 개념·18개 갈래를 확인했다. record_log 5, public_body 4, info_system 3, vulnerability 3, info_network 3이다. 현재 채팅의 활성 되물음 필터에는 record_log만 해당하며 공개 출처 전용 모드에서는 꺼진다. 다른 개념도 lexicon_lookup CLI에서 정의 계열·파생 결과를 소비하므로 미사용이라고 단정하지 않는다.

기존 loader에는 개념·갈래·좌표 검증·정의 계열·파생 규칙·사람이 정한 독해 원칙이 있다. 부족한 부분은 이를 모든 질문에 공통으로 연결하는 의미 계약이다. 질문 표현 매칭은 현재 문자열·제외어·단서 규칙이며 긴 문장의 의미를 완전히 해석하는 기능은 아니다.

기초 모델은 다음을 분리한다.

  • 표현: 실제 질문에 나온 단어·약칭·일상 표현. 일치한 위치와 제외어 근거를 남긴다. 표현 하나가 여러 개념 후보를 가질 수 있다.
  • 개념: 기존 안정 ID를 유지한다. 사전 밖의 표현은 unresolved로 남기고 일반 검색을 막지 않는다.
  • 갈래: 대상이 다른 갈래와 정의 출처가 다른 갈래를 구별한다. 모든 갈래를 자동 is_a 하위 개념으로 바꾸지 않는다.
  • 출처 결속: 정의 좌표에 기존 DB의 실제 판 ID·위치·본문 해시를 연결한다. 신규 버전 체계를 중복 만들지 않는다.
  • 관계: 명시 정의 차용, 같은 문장이라는 관측, 유사 문장 후보, 약칭 연결, 사람이 정한 원칙을 다른 타입으로 둔다. 유사도만으로 same_as나 전이 추론을 허용하지 않는다.
  • 질문 해석 결과: 표현 위치, 개념/갈래 후보, 대안, 부족한 맥락, 사전 판을 반환한다. 사전 버전 식별자와 후보별 origin(원문 정의/정책 원칙/유사도 등)은 James 소유의 신규 계약 제안이며 현재 필드가 있다고 주장하지 않는다. 검색에 사용 가능함과 의미 확정을 구별한다.

제안 객체 예: concept_id=info_system, sense_id=info_system.egov, axis=정의, definition_ref={article_id, article_version_id, locator, body_sha256}, interpretation={state:candidate, origin, matched_span, alternatives}, provenance={lexicon_version, source_snapshot_id}. 이는 아직 구현된 API나 저장 형식이 아니다.
